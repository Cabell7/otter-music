## Authentication and device setup

The static player shell is public. Private collection data requires a valid SYNC_KEY;
key creation and listing require the admin HttpOnly cookie. Admin login is /admin.
Create one key for yourself, then enter the same key on each device under Settings >
Data sync. The existing encrypted IndexedDB storage remembers it across visits.
Admin login expires separately; ordinary listening does not require the admin login.
Clearing site data or using another browser requires entering the key again.
SYNC_KEY is generated by the existing admin interface, not a build-time variable.

## Disabled routes

The deployed backend only mounts /auth and /sync/v2. /proxy, /music-api,
/podcast-api, /api/* and update relay routes return JSON 404. No mounted backend
route fetches audio, images, third-party pages or external APIs. Frontend music
lookup defaults to GD Studio's public API; audio is requested directly by the device.
The audio and download fallback proxy paths are disabled in code. Historical
HTTP audio URLs are upgraded to HTTPS; sources without HTTPS, CORS support or
browser-compatible access may fail. The Android release workflow is disabled.

## Sync and quota behavior

Visible online pages sync every two minutes. Edits are coalesced for 15 seconds,
with at least one minute between automatic attempts. Hidden/offline pages stop
automatic requests. Unchanged merged data does not produce a KV write. Four
devices continuously visible for 24 hours would generate about 2,880 scheduled
sync requests, plus edits, retries and management requests. Static files bypass
Functions via _routes.json. Cloudflare Free quotas are account-wide; separate
projects do not isolate quota exhaustion or account enforcement from email.

Existing timestamp-based merge and deletion tombstones are retained. Playlist
tracks now merge individually on the server; deletion tombstones last 180 days.
KV is eventually consistent and offers no atomic compare-and-swap. Version checks
reduce sequential conflicts but cannot prevent all simultaneous cross-region
lost updates. Avoid concurrent bulk edits and export JSON backups regularly.

## Backup and compatibility

Existing playlist JSON export/import and full local JSON backup/restore remain.
Otter imports a track array or an object with name and tracks. GD exports have
not been validated against a real user sample. The user will import manually;
if the file is rejected, preserve it and convert a copy without overwriting it.
Full backup can contain third-party settings: keep exports private.

## Use and limits

GD API and third-party streams may change, limit requests or be unavailable.
Hosting this application does not grant rights to third-party recordings. Use
authorized content and official services where needed; keep this deployment
personal and do not redistribute music or expose a proxy.
